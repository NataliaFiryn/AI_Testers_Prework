# Repository Instructions for Agents

Follow [CODING_STANDARDS.md](CODING_STANDARDS.md) for all implementation, formatting, code quality, and testing conventions.

Before changing code, review the relevant repository configuration, including `playwright.config.ts`, `eslint.config.mjs`, `.prettierrc`, and `tsconfig.json`. Treat these files as the executable source of truth. If documentation conflicts with configuration, flag the inconsistency instead of silently introducing a new convention.

Use the scripts in `package.json` to validate changes.

## Commit messages

Use Conventional Commits for every commit:

`<type>(optional-scope): <short description>`

Use a lowercase type such as `feat`, `fix`, `test`, `docs`, `refactor`, `chore`, or `ci`. Write the description in the imperative mood, keep it concise, and do not end it with a period.

Example: `test(smoke): add main page navigation checks`
